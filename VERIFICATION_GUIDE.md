# Verification guide for the pre-submission audit remediation

Audience: the auditor of the TOS manuscript and its companion archive.
Purpose: every remediation claim below is stated with the exact command that
verifies it against the published artefacts, so nothing needs to be taken on
trust. All commands run from the repository root with Python 3.10+,
`pandas`, `statsmodels` and `scipy` installed. Where an expected value is
stated, deviation from it should be treated as a finding.

Authoritative artefact: the repository at annotated tag `sweep-v1-audited-r1`
(github.com/tshivhidzo/cloud-storage-bench) and the corresponding NEW Zenodo
version in the 10.5281/zenodo.22032836 lineage. The earlier lightweight tags
(`sweep-v1`, `thesis-v1`, `sweep-v1-audited`) all point to the pre-remediation
commit c952e6ff and are superseded for audit purposes. Verify against the
`sweep-v1-audited-r1` commit, not against any transfer copy; the per-folder
`manifest.sha256` files inside the repository are the integrity ground truth
(Section 6).

## 0. Reproduce the entire results chain in two commands

```bash
python3 sweep/recompute_from_raw.py      # raw artefacts -> per-phase + per-run tables
BOOT_B=200 python3 sweep/refit_exponents.py   # tables -> exponents, pooled model, LaTeX table
```

Everything the manuscript reports comes from these two scripts' outputs
(`recompute-output/`). The LaTeX tables in the manuscript are `\input` files
generated by the second script; if your regenerated
`recompute-output/exponents_table.tex` differs from the manuscript's
`table_combined.tex`/`table_perop.tex`, the manuscript is wrong and that is
a reportable defect. The bootstrap uses seed 42; with `BOOT_B=200` expect
LR = 0.077 and bootstrap p in the 0.7--0.85 range (Monte Carlo variation).

## 2. Phase-level dataset (audit: sum-of-rates and p99 aggregation defects)

```bash
tail -n +2 recompute-output/per_phase.csv | wc -l        # expect 536
python3 - <<'EOF'
import csv
rows = list(csv.DictReader(open("recompute-output/runs_recomputed.csv")))

      and r["phases_present"]=="WRITE"]
```

Combined throughput is computed only as total MiB over total elapsed seconds
of both phases and only for runs possessing both phases; per-phase p99 comes
from elbencho's stdout percentile lines (the csv has no percentiles) or the
Azure runner's per-phase rows, and is never aggregated across phases. Verify
the implementation directly: `sweep/recompute_from_raw.py` (selection rule
for append-mode csvs is documented in the module docstring; stdout logs are
overwritten per attempt and therefore final).

## 6. Checksum integrity (your finding: 173 mismatches)

```bash
# Per-folder manifests: paths are relative to their own folder.
for d in results-aws results-azure results-gcp results-huawei results-alibaba \
         results-sweep-aws results-sweep-azure results-sweep-gcp \
         results-sweep-huawei results-sweep-alibaba; do
  echo -n "$d: "; (cd $d && sha256sum -c manifest.sha256 2>/dev/null | grep -c FAILED)
done
# Merged manifest: paths are relative to the REPOSITORY ROOT -- verify from
# the root, never from inside results-merged/ (doing so fails every line).
sha256sum -c results-merged/manifest.sha256 2>/dev/null | grep -c FAILED
```

Expected: 0 everywhere. Design: each folder's `manifest.sha256` is computed
over the published (redacted) artefacts; the host-generated originals,
computed over pre-redaction bytes, are preserved beside them as
`manifest.sha256.original-unredacted` so the provenance chain (host ->
redaction -> publication) is explicit rather than overwritten. No measurement
field was altered by any redaction; redactions touch only echoed command-line
credential values. You can confirm this by diffing any raw csv against its
quarantined or original counterpart where both exist: the only differing
bytes are `***REDACTED***` substitutions.

## 7. Statistical model (audit: workload omitted; boundary test; 5 groups)

`sweep/refit_exponents.py::pooled_model` implements:
log10(combined) ~ log10(conc) x C(paradigm) x C(workload), provider random
intercept, over the N = 356 runs with a defined combined rate (the four
write-only balanced runs carry no combined value by construction). The
random-slope LR is tested against the 50:50 chi2(1):chi2(2) mixture and by
parametric bootstrap whose null baseline is the FIXED-EFFECTS prediction
(exog @ fe_params) -- MixedLMResults.fittedvalues includes predicted random
effects and is deliberately not used. Bootstrap draws accumulate in
recompute-output/boot_lr.txt across batches (BOOT_B per batch, BOOT_SEED =
42, 43, 44, ...); library versions are recorded in pooled_model.txt, and
requirements-analysis.txt pins the environment.

Expected with the published data: LR = 0.444; mixture p = 0.6532;
bootstrap p = 0.4378 with the archived 200 draws (recomputing all three
batches with the documented seeds reproduces the draw file exactly). The
random-slope model reports converged = False -- an expected boundary
pathology when estimating a slope variance from five groups, disclosed in
the manuscript and the reason the bootstrap is reported at all. An earlier
distributed draft reported LR = 0.077 from a model that wrongly included
the four write-only runs; that defect and its correction are described in
manuscript Section 4.4.

## 8. Manuscript-to-archive number tracing

The manuscript source lives INSIDE this repository (`manuscript/`), so the
audit boundary includes it. Its two exponent tables are `\input` files that
must be byte-identical to the pipeline's generated output:

```bash
diff manuscript/table_combined.tex recompute-output/table_combined.tex && \
diff manuscript/table_perop.tex   recompute-output/table_perop.tex && echo IDENTICAL
```

Every number in the manuscript falls into one of three classes:
(a) the two `\input` tables above, generated by `refit_exponents.py`;
(b) numbers printed by the pipeline scripts and quoted in prose (attempt
    counts, phase counts, sizing mix, p99 growth medians, model statistics)
    -- each regenerated by the commands in this guide;
(c) configuration facts traceable to `configs/AS_EXECUTED_CONFIG.md` (with
    provider-documentation URLs inline and unrecoverable items marked) and
    `configs/host_state_extract.json` (fields extracted from retained host
    Terraform state, which itself is not published).
There is no class (d). The prior hand-transcribed table has been eliminated
as a production path, and "pre-registered" does not appear in the manuscript
(`grep -ci pre-regist manuscript/main.tex` returns 0).
